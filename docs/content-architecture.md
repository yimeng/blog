# 内容分类说明

这份说明用于维护博客的信息架构，不会被 Hugo 发布。博客的一级分类不追求覆盖所有技术名词，而是为长期写作提供稳定的入口：**系统、家、生活**。

## 一级分类

### 系统

记录人在复杂系统中工作、设计和动手实践的过程。这里的“系统”既包括技术系统，也包括组织、流程和产品。

- **工作回忆录**：从业经历、项目与故障案例、组织协作、职业判断和反思。
- **产品与平台**：企业 IT、基础设施平台、平台工程、云原生与研发效能产品的需求、边界和设计取舍。
- **工程实践**：可观测性、自动化、IaC、网络、Kubernetes、部署、工具与实验记录。

文章以“我经历了什么，以及这件事如何改变了我的判断”为主线时，属于工作回忆录；以“一个产品或平台应如何设计”为主线时，属于产品与平台；以具体实现、配置和实验为主线时，属于工程实践。三者可以共享标签，但一篇文章只选择最符合主叙事的一级分类。

### 家

记录技术如何克制、可靠地服务家庭生活，而不是把家变成办公室。

- 家庭网络与 Homelab
- 智能家居与自动化
- 家庭数据、隐私与 HomePulse

这里关注真实长期使用中的可靠性、可维护性和隐私，不以设备评测或参数罗列为中心。

### 生活

记录工作与技术之外的人、地点和时间。

- **日常**：物件、阅读、饮食、随笔与小观察。
- **记忆**：故乡、成长、家人与人生片段。
- **行走**：旅行、城市、通勤、迁徙与空间观察。

“来处”不作为一级分类使用；它可以保留为“故乡与迁徙”或“来处”这样的系列名称，以承载更具体的写作线索。

## 分类、系列与标签

三者分工不同：

| 类型 | 回答的问题 | 例子 |
| --- | --- | --- |
| 分类 | 这篇文章属于哪个世界？ | 系统、家、生活 |
| 系列 | 它在连续讲什么？ | 一线十七年、企业 DNS 平台、HomePulse |
| 标签 | 它涉及哪些具体主题？ | DNS、平台工程、监控、东北、阅读 |

避免将“传统运维”“云原生”“AI”等变化较快、彼此重叠的概念设为一级分类；它们更适合作为系列或标签。

## 存量内容的归属

- 现有“工程实践”内容归入 **系统**，可保留“工程实践”作为系列或聚合入口。
- 现有“智能家居”和“家庭实验室”内容归入 **家**。
- 工作培训、项目复盘与组织观察归入 **系统** 下的工作回忆录。
- DNS 平台等围绕产品边界与取舍展开的文章归入 **系统** 下的产品与平台。

不需要为迁移旧文章而勉强改写内容；分类应服务阅读和后续写作，存量文章可以随着重写或新增时逐步整理。
