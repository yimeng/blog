## 监控与理解的本质区别

```
监控：这个传感器现在是什么值？
理解：家里刚才发生了什么活动？
```

**监控是"看数值"，理解是"懂活动"**。

**这不是文字游戏，是数据工作的根本目标差异**：
- 监控关注"设备状态"（灯是开是关、温度是多少）
- 理解关注"家庭活动"（谁在洗澡、洗衣机在干什么、老人是否安全）

## 单源数据的局限

### 只有功率数据

```
知道：有设备在用（功率在涨）
不知道：是哪个设备（功率形态可能相似）
```

**局限**：功率指纹会重叠（吹风机和热风枪、电饭煲和电水壶，功率形态可能一样）。

**为什么不能靠功率识别设备**：
- 吹风机低档位可能和热风枪低档位功率相近
- 电饭煲保温阶段和电水壶保温阶段功率相近
- **功率形态不是设备的唯一标识**

### 只有水流量数据

```
知道：在用水（水流量在涨）
不知道：是洗澡还是洗衣还是冲马桶
```

**局限**：水流量形态可能相似（洗澡和洗衣都是持续用水）。

**为什么不能靠水流量识别活动**：
- 洗澡和洗衣都是持续用水，流量形态可能相似
- 冲马桶是瞬时大量用水，和洗澡的持续用水不同
- **水流量形态不是活动的唯一标识**

### 只有状态数据

```
知道：浴霸开了（switch on）
不知道：为什么开（是洗澡还是取暖还是换气）
```

**局限**：状态开关不能说明活动原因。

**为什么不能靠状态开关理解活动**：
- 浴霸开了可能是洗澡、可能是取暖、可能是换气、可能是照明
- **状态开关只是"开了"，不知道"为什么开"**

## 跨源数据的价值

### 案例 1：洗澡识别

```
燃气燃烧 on + 水流量 > 5L/min + 浴霸 on + 湿度上升
  → 高置信度"有人在洗澡"
```

**三个独立数据源交叉验证**，比单看任何一个都准。

**为什么跨源验证更可靠**：
- 燃气燃烧：说明在烧热水（可能是洗澡或厨房用热水）
- 水流量大：说明在大量用水（可能是洗澡或洗衣）
- 浴霸开：说明浴室有人活动（可能是洗澡或换气）
- **三者联合 = 高置信度"有人在洗澡"**

### 案例 2：洗衣机程序识别

```
洗衣机程序 = 脱水 + 水位下降 + 功率周期波动
  → 知道"洗衣机在脱水"，不需要人告诉
```

**程序状态 + 水位 + 功率三者联合**，可以精确识别洗衣机当前阶段。

**为什么需要多源**：
- 程序状态：洗衣机的当前程序（洗涤/漂洗/脱水）
- 水位：当前水位变化（进水/排水）
- 功率：功率周期波动（脱水时功率周期变化）
- **三者联合 = 精确识别洗衣机当前阶段**

### 案例 3：老人夜间安全

```
人体存在传感器（北卧室）on→off + 门磁 off→on + 时间 02:00
  → 老人夜间起夜，去卫生间
```

**人体存在 + 门磁 + 时间戳**，可以还原老人的夜间活动轨迹。

**为什么这个组合有效**：
- 人体存在传感器：北卧室有人活动（老人起床）
- 门磁：门开了（老人走出房间）
- 时间戳：凌晨 2 点（夜间活动，需要关注）
- **三者联合 = 还原老人夜间起夜去卫生间的完整轨迹**

## 数据挖掘 = 多源交叉验证

**原则**：
- **不跨源推断**：A 源的现象不能解释 B 源（水压 0.33 bar 不能直接推出"上游"）
- **不用均值抹尖峰**：原始样本做事件分析，不是分钟均值
- **标注优先于算法**：用户说"刚才关了浴霸"，算法去验证而不是猜

**关键**：跨源数据的价值在于**互相印证**，不是互相替代。

**为什么不能跨源推断**：
- 水压高不能直接推出"上游"（可能是泵的问题）
- 功率下降不能直接推出"停机"（可能是设备故障）
- **每个数据源只能说明它自己看到的现象**，不能解释其他源的现象

## 数据实验室的目标

**数据实验室的目标不是"存数据"，是"理解家里发生了什么"**：

```
不是"这个传感器现在是什么值"
而是"家里刚才发生了什么活动、谁在做什么、设备在干什么"
```

**具体目标**：
- 谁在洗澡？（水+气+浴霸联合判断）
- 洗衣机洗到哪一步？（程序+水位+功率联合判断）
- 老人夜间是否安全？（人体存在+门磁+时间联合判断）
- 哪台电器最耗电？（回路功率+设备身份映射）

**从监控到理解的跃迁**：
- 监控：这个传感器现在是什么值？
- 理解：家里刚才发生了什么活动？

## 通用原则

**数据挖掘 = 多源交叉验证，不是单源拟合**：

- 单源数据只能"看数值"
- 跨源数据才能"懂活动"
- **数据实验室的目标是理解家庭活动，不是收集数据**

**从监控到理解的跃迁**：
- 监控：这个传感器现在是什么值？
- 理解：家里刚才发生了什么活动？

**数据实验室的价值不在于"存了多少数据"，而在于"能理解多少活动"**。

## 误区与边界

### 误区 1：以为"数据越多越好"

实际上：
- 数据多不等于信息多（重复值、噪声、无关数据）
- 单源数据多不等于能理解活动（需要跨源验证）
- **数据价值在于"能理解多少活动"，不在于"存了多少数据"**

### 误区 2：以为"算法能自动理解活动"

实际上：
- 活动识别需要多源交叉验证（不是单源拟合）
- 算法可以辅助提取证据（ΔW、驻留时间、周期通断），但不能替代多源验证
- **算法是辅助，多源验证是核心**

### 边界：什么时候单源数据也够

- 明确知道设备身份（比如"这是洗衣机"）→ 单源功率也能分析该设备的行为
- 明确知道活动类型（比如"这是洗澡"）→ 单源水流量也能分析用水量
- **但"识别活动"本身需要多源验证**

## 原则提炼

1. **监控是"看数值"，理解是"懂活动"**：数据实验室的目标是理解家庭活动，不是收集数据
2. **单源数据的局限**：功率/水流量/状态开关都不能单独识别活动
3. **跨源数据的价值**：多源交叉验证才能高置信度识别活动
4. **不跨源推断、不用均值抹尖峰、标注优先于算法**：数据可信度比算法复杂度重要

**从监控到理解的跃迁**：从"这个传感器现在是什么值"到"家里刚才发生了什么活动"。
