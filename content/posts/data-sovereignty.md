## 厂商云的问题

**数据归属权在厂商，不在你**。

```
米家云、美的云、涂鸦云……
  → 数据存在厂商的服务器上
  → 厂商可以限流、改接口、停服
  → 你的家庭活动数据，别人比你更清楚
```

**具体风险**：
- 云停服：数据直接不可用（历史数据可能永久丢失）
- 限流：高频采集被限制（"每分钟最多 60 次"）
- 改接口：API 变更导致你的采集器失效
- 隐私：你的作息、活动、习惯，厂商比你更清楚

## 家庭数据是最隐私的数据

**家庭数据比你想的更敏感**：
- 什么时候睡觉、什么时候起床
- 什么时候洗澡、洗多久
- 什么时候出门、什么时候回家
- 老人夜间是否起夜、孩子是否在家

**这些数据一旦上云，就等于把家庭生活完全暴露给厂商**。

## 留在家里：数据主权在自己手里

```
能直采就直采，能不经过云就不经过云。

直采的好处：
- 数据主权在自己手里
- 断网也能用（本地分析不依赖云）
- 可以按自己的意愿保留/删除/分析
- 不需要向厂商申请权限、担心限流
```

**实测案例**：
- 泵的 BLE 数据通过自研 ESP32 网关直采，43 个字段完整
- 电表通过 ESPHome 直发 MQTT，原始裸值无损失
- 温湿度传感器通过 HA 本地接入，不经过米家云

## 去中心化的价值

**去中心化不是技术潮流，是数据主权的必然选择**：

| 方面 | 厂商云 | 家庭侧 |
|---|---|---|
| 数据归属 | 厂商 | **自己** |
| 可用性 | 依赖云 | **本地可用** |
| 隐私 | 暴露给厂商 | **自己控制** |
| 保留期 | 厂商决定 | **自己决定** |
| 分析能力 | 厂商限制 | **完全自由** |

## 通用原则

**家庭数据是最不该上云的数据**。

- 能直采就直采（设备协议可达就直采）
- 能不经过云就不经过云（HA 本地接入、自研网关）
- 数据主权比便利性重要（宁可多维护一个采集器，也不把数据交给厂商）

**数据主权不是技术选择，是生活方式选择**。
